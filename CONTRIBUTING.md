# Contribuir

Cambios pequeños, con tests y documentación. Flujo: issue → plan → rama `feat/`, `fix/` o `chore/` →
implementación con tests → `make check` → PR. Decisiones de arquitectura: ADR en `docs/adr/`.
Nunca incluir secretos, claves, datos personales ni artefactos de modelos sin licencia/procedencia
verificadas. Las fronteras de `.importlinter` no se relajan sin un ADR.
